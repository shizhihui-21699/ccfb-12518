# PDF 涂黑检查工具（RedactionCheck）

面向法务场景的 Blazor Server 工具，解决一个真实问题：**用黑色图形/高亮“盖住”PDF 里的敏感文字，
并不会删除底层文字，对方仍可选中、复制、搜索或重新提取出来。**

本工具做两件事：

1. **检查**：上传 PDF，逐页找出“被图形视觉遮挡、但底层文字仍可提取”的位置，并列出对方实际能恢复出的内容。
2. **真正涂黑**：删除覆盖区域内的文字绘制、图像绘制与遮盖注释，重绘不透明黑框，重新生成文件，
   并对新文件**自动复查一遍**，确认原始泄漏词已无法再被提取。

## 支持识别的“假涂黑”方式

| 方式 | PDF 表现 | 检测手段 |
| --- | --- | --- |
| 不透明填充黑框 | `f`/`f*`/`B*` 等路径填充 | 重建图形状态（CTM、填充色），取填充包围盒与文字求交 |
| 粗描边“记号笔” | 大线宽 `S` 描边 | 线宽 ≥ 4pt 的描边按笔宽膨胀后与文字求交 |
| 不透明图片覆盖 | `Do` 绘制图像 XObject | 按当前 CTM 计算图像包围盒与文字求交 |
| 遮盖注释 | Square/Highlight/FreeText 等注释 | 读取注释 `Rect`，与文字求交 |

文字与遮挡的重叠面积达到词框 25% 即判为泄漏，并把同一遮挡下的词聚合成一条“可恢复内容”。

## 解决方案结构

```
RedactionCheck.sln
├─ src/RedactionCheck.Core/            # 不依赖 UI 的核心库（.NET 8 类库）
│  ├─ Geometry/                        # PdfRect、仿射变换 Matrix3x2
│  ├─ Models/                          # 扫描报告、泄漏项、复查结果等模型
│  ├─ Scanner/
│  │  ├─ GraphicsStateWalker.cs        # 内容流算子 → 图形状态 → 遮挡元素
│  │  └─ PdfLeakScanner.cs             # 遮挡 × 可提取文字求交，产出报告
│  ├─ Fonts/PageGlyphIndex.cs          # PdfPig 字形位置索引（按用户空间原点匹配）
│  └─ Redaction/
│     ├─ ContentStreamTokenizer.cs     # 手写 PDF 内容流词法分析器
│     ├─ ContentStreamRewriter.cs      # 删除区域内 Tj/TJ 字形、Do 图像、路径
│     ├─ TextStreamState.cs            # BT/ET/Tm/Td 文本状态机
│     └─ PdfRedactor.cs                # PdfSharp 改写文档 + 重绘黑框 + 复查
├─ src/RedactionCheck.Web/             # Blazor Server 交互界面（上传/报告/下载）
├─ tools/RedactionCheck.SampleGenerator/ # 生成 6 份不同遮挡方式的样例 PDF
└─ tests/RedactionCheck.Tests/         # xUnit：几何、词法、端到端涂黑与复查
```

### 关键技术选择

- **PdfPig 0.1.16**：读取算子流、词/字形精确包围盒、注释、图像，用于检测与复查。
- **PdfSharpCore 1.3.67**：在保留原文档结构的前提下改写页内容流、删除注释、追加黑框并另存。
- **手写内容流词法分析器 + 改写器**：不依赖“整页重排”，只动需要删除的绘制指令，最大限度保留原排版。
- **字形删除用 TJ 字距空位实现**：删掉区域内的字符串片段，用等量负向位移占位，
  不修改文本矩阵（Tm），因此不会错位或把后续行重复输出。
- **多内容流安全**：每个内容流用独立改写器（独立图形/文本状态），共享一份按位置匹配的字形索引，
  避免跨流错位。

## 构建与运行

需要 .NET 8 SDK。

```bash
# 还原 + 编译整个解决方案
dotnet build RedactionCheck.sln

# 运行单元/端到端测试（21 个）
dotnet test tests/RedactionCheck.Tests

# 启动 Blazor 界面
dotnet run --project src/RedactionCheck.Web
# 浏览器打开控制台输出的地址（默认 http://localhost:5xxx）
```

### 生成样例文件

```bash
dotnet run --project tools/RedactionCheck.SampleGenerator -- samples
```

会在 `samples/` 生成 6 份“视觉遮挡但文字仍可复制”的 PDF：

1. `01-填充黑框-假涂黑.pdf` —— 不透明填充矩形盖住银行账号/身份证/手机号
2. `02-粗描边线-记号笔.pdf` —— 宽描边线条盖住奖金/期权
3. `03-注释方块-遮盖.pdf` —— Square 注释盖住姓名/住址
4. `04-不透明图片-遮盖.pdf` —— 黑色 PNG XObject 盖住负债/诉讼金额
5. `05-变换与裁剪路径.pdf` —— 经 `cm` 变换 + 裁剪路径的填充框（考验坐标变换）
6. `06-多页混合遮挡.pdf` —— 三页：填充框 / 干净页 / 粗描边

> 样例使用系统 Arial Unicode 字体嵌入中文（macOS 路径 `/System/Library/Fonts/Supplemental/`）。
> 在其他平台生成时，请把 `SampleFileBuilder` 里的字体路径改为本地含 CJK 字形的 TTF。

## 涂黑做了什么（与“画黑框”的区别）

对每个检测到的遮挡区域，输出文件会：

- 从内容流中**删除区域内的 Tj/TJ 文本片段**（不是盖在上面，而是绘制指令本身消失）；
- **删除区域内的 `Do` 图像绘制**与命中区域的路径填充/描边；
- **删除命中区域的遮盖注释**；
- 在原位置重绘一个不透明黑色矩形，保持视觉上的“涂黑”外观；
- 复查：重新扫描输出文件，并把原始每个泄漏词放到新文件的完整提取文本里逐一比对，
  全部不可提取才判定通过。

复查结果（逐词探针、残留计数）直接展示在界面上，未通过会明确提示“请勿外发”。

## 安全与边界说明

- 文件只在当前 Blazor 电路（scoped 会话）的内存中处理，**不落服务器磁盘、不写共享状态**；
  下载通过 JS 流式互操作直接回传浏览器。
- 本工具处理的是**内容流里可提取的文字与常规图像/矢量/注释**。以下情况需另行评估：
  - 文字被栅格化进扫描图像（本就不可提取，黑框只起视觉作用，需 OCR 后再处理图像区域）；
  - 嵌入文件附件、文档级元数据、书签/大纲里的敏感信息（当前不在页内容流处理范围）；
  - 加密/带权限密码或结构高度异常的 PDF。
- 涂黑后请始终以界面“复查通过”为准再外发；工具不会静默放行复查失败的文件。
